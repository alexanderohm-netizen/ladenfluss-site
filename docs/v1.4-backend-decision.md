# Ladenfluss v1.4 — Backend-Entscheidung

## Empfehlung: Supabase + Vercel

Für v1.4 soll Supabase die erste Backend-Basis bilden.

### Warum
- Authentifizierung und Postgres-Datenbank in einem System
- E-Mail/Passwort, E-Mail-Bestätigung und Passwort-Reset
- Row Level Security für echte Mandantentrennung
- EU-Region Frankfurt möglich
- native Vercel-Integration
- später geeignet für Unternehmen, Filialen, Mitarbeiter, PEP, Zahlenfluss und Warenfluss

### Sicherheitsregeln
- Browser erhält ausschließlich URL + Publishable Key.
- Secret-/Service-Role-Key niemals in HTML oder Browser-JavaScript.
- Jede fachliche Tabelle erhält RLS.
- Jeder Datensatz wird über company_id bzw. branch_id einem Mandanten zugeordnet.
- Zugriff wird nicht nur in der Oberfläche versteckt, sondern in der Datenbank geprüft.
- Login wird erst aktiviert, wenn RLS und Tabellen eingerichtet und getestet sind.

### Umsetzung
1. Supabase-Projekt in EU/Frankfurt anlegen.
2. Schema aus `supabase/schema.sql` anwenden.
3. E-Mail-Verifizierung aktiv lassen.
4. Vercel-Umgebungsvariablen setzen.
5. Kundenkonto mit Supabase Auth verbinden.
6. Onboarding schreibt Unternehmen + erste Filiale.
7. Mitarbeiter & PEP von lokalem Prototyp-Speicher auf Datenbank umstellen.

## Noch nicht Teil dieses Commits
- keine echten Zugangsdaten
- keine Secret Keys
- keine produktive Datenbankverbindung
- keine Migration bestehender Browserdaten
